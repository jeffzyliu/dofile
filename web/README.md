# dofile web demo

The dofile engine running in the browser: a code editor, a file panel, Run and Break, the log and graphs. There is no
server. The engine is the same Python (`src/dofile/`, with the vendored OpenDTA) run by [Pyodide](https://pyodide.org)
(CPython compiled to WebAssembly) in a Web Worker. Your files live in the page's own store in IndexedDB, so they survive
a reload (data in memory does not) and the page can list, edit and download them with no engine; the worker copies them
into its `/work` folder when it starts and writes back what each run changed.

This is Phase 2 of the project; the plan, decisions and measurements are in [`../docs/phase2-plan.md`](../docs/phase2-plan.md).
The page is Preact with signals on the project's own CSS (`src/app/`); prototype 1 is being built to
[`../docs/design/SPEC.md`](../docs/design/SPEC.md) (status: [`../docs/phase2-plan.md`](../docs/phase2-plan.md)).

## Setup

Needs Node 26 and [uv](https://docs.astral.sh/uv/) (the scripts build the dofile wheel with `uv build`).

```bash
cd web
npm install        # `npm ci` for a clean install from the lockfile
```

## Scripts

Run them from `web/` with `npm run <name>`. Those that need the dofile wheel build it first (`npm run wheel`, which writes
`../dist/dofile-*.whl`).

### Memory snapshot

The normal start installs the wheel and imports numpy, scipy and matplotlib: about 5 s on a fast machine. A snapshot is a
saved Pyodide heap with all that already done, so the page restores it instead. **That is the page's default start**;
`?snapshot=0` is the normal start. There is no fallback: with no snapshot (a fresh checkout under `npm run dev`) or a stale one, the
engine does not start and the page gives the cause (it does not name `?snapshot=0`, a diagnostic mode for developers). Why it works, how it is built and what it costs:
[`../docs/pyodide-snapshot.md`](../docs/pyodide-snapshot.md).

| Script           | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Time   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| `snapshot`       | Builds the wheel, then `scripts/make-snapshot.mjs` writes `public/snapshot/` (gitignored): the heap image and the site-packages bundle, both brotli-compressed (about 42 MB; 229 MB uncompressed), plus a manifest. Needs the network once (micropip fetches openpyxl). **Rebuild it after any change to the dofile code, a wheel in `wheels/` or the Pyodide version**: the manifest (the snapshot's build record, not deployed) holds the wheels' SHA-256s and the Pyodide version, `vite build` fails on a stale snapshot, and in development the page refuses it ("run `npm run snapshot`"; `scripts/build-id.ts`). **One tab at a time.** The tab that holds the Web Lock `dofile-engine` owns the files and the engine; a second tab is asked
whether to take over, and the tab that loses the lock ends its engine. Web Locks need a secure context: over plain HTTP on a
LAN (`npm run dev` opened from a phone) there is no lock, and every tab owns the engine. The deployed site (HTTPS) is not
affected.

**The test hook.** With `?test` in the URL the page sets `window.__dofile = { engine, store, start, persisted, engineBytes, state, run,
breakRun, reset, selection, drops }` for the browser tests (`e2e/step2.spec.ts`; the list says what each is in `CLAUDE.md`); with `?test=manual` it also starts no engine until the test calls `start()`.
Without the flag there is no such object.

**The site's addresses:** two origins. The landing page is `/` and the commands page `/commands/` of the site (`https://dofile.dev/`, built into `dist/site/`); the editor is a single-page app at the root of its own origin (`https://app.dofile.dev/`, `dist/app/`; `/?test` and the other flags as before). The editor's location is one setting, `scripts/urls.ts`; the steps, the redirects and what stays behind at the old origin: `../docs/design/SPEC.md`, section 8, "URLs".
`npm run build` makes `dist/app/` (the editor and every file it loads, and its `_headers`) and then `dist/site/` (the two static pages, `index.html` and `commands/index.html`, with their own `assets/`, and a `_headers` with noindex in a build that is not production's).

**The download size** shown before the engine is fetched is a number the build writes into `dist/app/index.html`
(`<meta name="dofile-engine-bytes">`, read into `engineBytes` in `src/app/state.ts`): the compressed total of
`dist/app/start-files.json`, which lists only the editor's files. The dev server writes the same tag from `public/` (without
the page's own files). The landing page states the same number, rounded.

`vite.config.ts` sets the cross-origin isolation headers (`COOP`/`COEP`) in the dev server (on every response) and in
preview of the editor (every path, as the host does). They give the editor a `SharedArrayBuffer`, which Break needs; **a static host
must send the same two headers on every path of the editor** (`dist/app/_headers`); the pages need none. Without them Break can only reset
the engine. The snapshot start takes Pyodide's runtime (`pyodide.asm.wasm`, `python_stdlib.zip`, `pyodide-lock.json`) from the
page's own origin (`public/pyodide/`), so it asks nothing of another origin; `?snapshot=0` loads the runtime and the packages
from the jsDelivr CDN, at the same version as the `pyodide` npm package.

## Cloudflare Workers (static assets)

Two Workers, each a static-assets-only Worker with `html_handling: "auto-trailing-slash"` (`/commands` goes to `/commands/`) and `not_found_handling: "none"` (a missing page is a 404), a custom domain and the `workers.dev` address (previews use it):
`wrangler.jsonc` is the site's (Worker `dofile`, `dist/site/`, `dofile.dev`) and `wrangler.app.jsonc` the editor's (Worker `dofile-app`, `dist/app/`, `app.dofile.dev`; its `_headers` isolates every path). A bare `wrangler deploy` deploys the site only: use `--config wrangler.app.jsonc` for the editor.
`npx wrangler login` once, then `npm run cf:dev` (local, workerd: the site on port 8787 and the editor on 8788, built with links to those; `DOFILE_SITE_URL` and `DOFILE_EDITOR_URL` override them, for a phone on the LAN) or `npm run deploy` (which runs `lint:strict` first, then deploys the editor and the site). Both build the snapshot first (the page
starts from it by default, and `public/snapshot/` is gitignored, so a page built without one would not start). Each asset must
be under 25 MiB; the two snapshot files are about 20 MB, so they fit with little room to spare. A snapshot built with
`SNAPSHOT_QUALITY=5` (as the e2e tests and CI build it) does not: its heap is about 26.5 MB, and `wrangler dev` refuses it
("Asset too large"); `npm run cf:dev` builds the default quality 11 (about 3 min), which it serves (checked in step 5). The deploy and preview builds (`.github/actions/build-web`) fail the job when any file in `dist/app/` or `dist/site/` is over 25 MiB and warn over 23 MiB, because the brotli-11 snapshot is built only there.

`.github/workflows/deploy.yml` runs on every push to `main` (and by hand): it calls `ci.yml`, `web.yml` and `lint.yml` on that
commit and deploys both Workers only if all three passed and the commit is still the tip of `main`. The build (shared with
previews: `.github/actions/build-web`) makes the snapshot too, cached on a hash of its inputs. It needs the repo secrets
`CLOUDFLARE_API_TOKEN` (the "Edit Cloudflare Workers" template) and `CLOUDFLARE_ACCOUNT_ID`.

`.github/workflows/preview.yml` builds both parts for a pull request from a branch of this repo (not a fork) with the links
pointing at `https://pr-<N>-dofile-app.<subdomain>.workers.dev/` (editor) and `https://pr-<N>-dofile.<subdomain>.workers.dev/`
(pages), uploads them with `wrangler versions upload --preview-alias pr-<N>` (production does not change) and keeps one
comment on the pull request with the two addresses. `<subdomain>` is the repo variable `CLOUDFLARE_WORKERS_SUBDOMAIN`.

## CI

`.github/workflows/web.yml` runs four jobs on every pull request and on every push to `main` (started by `deploy.yml` there, one run per commit, so a merge's tree is tested; a pull request that changes nothing under `web/` or the Python build inputs skips the test jobs), and it can be started by hand. `deploy.yml` deploys only after it, `ci.yml` and `lint.yml` passed:

- **types, unit tests, build:** `npm run check`, a check that `commands.json` is up to date, `npm test`, `npm run build`.
- **format and lint (Biome):** `npm run lint:strict`: the format, the import order and the lint rules; a warning fails.
- **browsers:** `npm run e2e` on Ubuntu, a matrix of four jobs, one Playwright project each (Chromium, Firefox, WebKit,
  iPhone profile), each on its own runner with a 30-minute limit; Playwright's results are kept as an artifact on failure.
- **memory snapshot:** `npm run snapshot`, then `npm test` (so the native-library test runs) and `npm run check-snapshot`.
  On a pull request it runs only when the pull request changes one of its inputs (the `ENGINE` list in `web.yml`: the
  Python engine and its build files, the extra wheels, the Pyodide version, `web/src/engine/`, the snapshot scripts and
  tests, the conformance corpus and `tests_opendta/`); on a push to `main` it always runs.

`check-pytest` and `check-numeric` are run by hand. The Python suite is `.github/workflows/ci.yml`.
