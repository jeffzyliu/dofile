# dofile web: development and architecture

The web editor (`https://app.dofile.dev/`) and the landing and commands pages (`https://dofile.dev/`). What dofile is and
how to use it: the [main README](../README.md).

The editor runs the dofile engine (the same Python as `src/dofile/`, with the vendored OpenDTA) in
[Pyodide](https://pyodide.org) (CPython compiled to WebAssembly) inside a Web Worker. There is no server: the hosts serve
static files only. Files live in the page's own IndexedDB store, so they survive a reload (data in memory does not) and
the page lists, edits and downloads them with no engine; the worker copies them into its `/work` folder when it starts and
writes back what each run changed. The page is Preact with signals on the project's own CSS (`src/app/`), built to
[`../docs/design/SPEC.md`](../docs/design/SPEC.md). Plan, decisions and status: [`../docs/phase2-plan.md`](../docs/phase2-plan.md).
Data flow through the engine code: [`../docs/web-engine-data-flow.md`](../docs/web-engine-data-flow.md); the page's focus,
runs, open files and log links: [`../docs/web-page-flows.md`](../docs/web-page-flows.md). Rules for changing the code:
[`CLAUDE.md`](CLAUDE.md).

## Setup

Node 26 and [uv](https://docs.astral.sh/uv/) (the scripts build the dofile wheel with `uv build`).

```bash
cd web
npm install        # or `npm ci`: a clean install from the lockfile
npx playwright install   # once, for the e2e tests
```

## Scripts

Run from `web/` with `npm run <name>`. Scripts that need the dofile wheel build it first (`npm run wheel`, which writes
`../dist/dofile-*.whl`).

### Memory snapshot

The normal start installs the wheel and imports numpy, scipy and matplotlib (about 5 s on a fast machine). A snapshot is
a saved Pyodide heap with that done, and **it is the page's default start**; `?snapshot=0` is the normal start, a
diagnostic mode for developers. There is no fallback: with no snapshot or a stale one the engine does not start and the
page gives the cause (it does not name `?snapshot=0`). How it works and what it costs:
[`../docs/pyodide-snapshot.md`](../docs/pyodide-snapshot.md).

| Script           | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Time   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| `snapshot`       | Builds the wheel, then `scripts/make-snapshot.ts` writes `public/snapshot/` (gitignored): the heap image and the site-packages bundle, brotli-compressed (about 42 MB; 229 MB uncompressed), and a manifest. Needs the network once (micropip fetches openpyxl). **Rebuild after any change to the dofile code, a wheel in `wheels/` or the Pyodide version**: the manifest (not deployed) holds the wheels' SHA-256s and the Pyodide version, `vite build` fails on a stale snapshot, and in development the page refuses it (`scripts/build-id.ts`). The browser's own brotli decoder unpacks it when there is one (much faster on an iPhone), else brotli-wasm; `?brotli=wasm` forces wasm. Timings: the client's `startup`, a run's `timing`, the worker's `[dofile] snapshot start` console line. `SNAPSHOT_OUT=dir` writes elsewhere; `SNAPSHOT_STRIP_DOCS=0` keeps docstrings and asserts. | ~3 min |
| `check-snapshot` | Starts the engine from the snapshot with the page's own restore code and runs the conformance corpus, the probes, native-library calls and the Stata 14 reference cases, one process per case. Builds the wheel first and exits 2, running nothing, when the snapshot is stale or missing. `-- --normal`: no snapshot (the baseline, no check); `-- --cases a,b` picks cases; `-- --dir path` checks another snapshot folder.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | ~4 min |

## How the editor runs

**One tab at a time.** The tab holding the Web Lock `dofile-engine` owns the files and the engine; a second tab is asked
whether to take over, and the tab that loses the lock ends its engine. Web Locks need a secure context: over plain HTTP on
a LAN there is no lock and every tab owns the engine. HTTPS is not affected.

**The test hook.** With `?test` in the URL the page sets `window.__dofile = { engine, store, start, persisted,
engineBytes, state, run, breakRun, reset, selection, drops, focusWanted }` for the browser tests (the object is in
`src/main.tsx`, its type `DofileHook` is exported from there); `?test=manual` also starts no engine until the test calls `start()`. Without the flag there is
no such object.

**The download size** shown before the engine is fetched is written by the build into `dist/app/index.html`
(`<meta name="dofile-engine-bytes">`, read as `engineBytes` in `src/app/state.ts`): the `download` size of
`dist/app/start-files.json`: the compressed bytes of the files the page fetches (the snapshot, the runtime, the brotli decoder),
not of the page's own files, which came with it, plus a lazy snapshot's graphics part (fetched after the start; "Graphs loading" and a ring show its progress). The download's progress counts the files before the start, and its dialog names the part's size under the bar. The dev server writes the same tag from `public/` (without the
page's own files). The landing page states the same number, rounded.

**Cross-origin isolation.** `vite.config.ts` sets `COOP`/`COEP` in the dev server (every response) and in the editor's
preview (every path). They give the editor a `SharedArrayBuffer`, which Break needs; **a static host must send both
headers on every path of the editor** (`dist/app/_headers`); the pages need none. Without them Break can only reset the
engine. The snapshot start takes Pyodide's runtime (`pyodide.asm.wasm`, `python_stdlib.zip`, `pyodide-lock.json`) from
the page's own origin (`public/pyodide/`), so it asks nothing of another origin; `?snapshot=0` loads the runtime and
packages from the jsDelivr CDN, at the `pyodide` npm package's version.

## Two origins, two Workers

The landing page (`/`) and commands page (`/commands/`) are the site, `https://dofile.dev/`, built into `dist/site/` (the
two static pages with their own `assets/`, and a `_headers` with noindex in a non-production build). The editor is a
single-page app at the root of its own origin, `https://app.dofile.dev/`, built into `dist/app/` (the editor, every file it
loads, and its `_headers`; `/?test` and the other flags as above). The editor's location is one setting,
`scripts/urls.ts`; the steps, redirects and what stays behind at an old origin: SPEC section 8, "URLs".

Each is a static-assets-only Cloudflare Worker with `html_handling: "auto-trailing-slash"` (`/commands` goes to
`/commands/`), `not_found_handling: "none"` (a missing page is a 404), a custom domain and its `workers.dev` address
(previews use it): `wrangler.jsonc` is the site's (Worker `dofile`, `dist/site/`, `dofile.dev`), `wrangler.app.jsonc` the
editor's (Worker `dofile-app`, `dist/app/`, `app.dofile.dev`; its `_headers` isolate every path). A bare `wrangler deploy`
deploys the site only; the editor needs `--config wrangler.app.jsonc`.

`npx wrangler login` once, then:

- `npm run cf:dev`: both Workers locally in workerd (site on 8787, editor on 8788, built to link to those;
  `DOFILE_SITE_URL` and `DOFILE_EDITOR_URL` override them, e.g. for a phone on the LAN).
- `npm run deploy`: `lint:strict`, the snapshot, a `DOFILE_URLS=production` build, the size check, then the editor and the
  site.

Both build the snapshot first (the page starts from it, and `public/snapshot/` is gitignored). Each asset must be under
25 MiB; the two quality-11 snapshot files are about 20 MB each, with little room to spare. A `SNAPSHOT_QUALITY=5` snapshot
(as e2e and CI build it) does not fit: its heap is about 26.5 MB and `wrangler dev` refuses it ("Asset too large"), so
`cf:dev` builds the default quality 11 (about 3 min). The size check (`scripts/check-sizes.ts`, run by `npm run deploy`
and by the deploy and preview builds in `.github/actions/build-web`) fails when a file in `dist/app/` or `dist/site/` is
over 25 MiB and warns over 23 MiB.

## CI and deploys

- `.github/workflows/web.yml`, on every pull request, every push to `main` (through `deploy.yml`, one run per commit) and
  by hand. A pull request that changes nothing under `web/` or the Python build inputs skips the test jobs.
  - **types, unit tests, build:** `npm run check`, a check that `commands.json` is current, `npm test`,
    `DOFILE_URLS=production npm run build`.
  - **format and lint (Biome):** `npm run lint:strict`; a warning fails.
  - **browsers:** `npm run e2e` on Ubuntu, one job per Playwright project (Chromium, Firefox, WebKit, iPhone), each on its
    own runner with a 30-minute limit; Playwright's results are kept as an artifact on failure.
  - **memory snapshot:** `npm run snapshot`, then `npm test` (so the native-library test runs) and `npm run check-snapshot`.
    On a pull request only when one of its inputs changed (the `ENGINE` list in `web.yml`: the Python engine and build
    files, the extra wheels, the Pyodide version, `web/src/engine/`, the snapshot scripts and tests, the conformance
    corpus, `tests_opendta/`); on `main` always.
- Deploys: `.github/workflows/deploy.yml` (production, after `ci.yml`, `web.yml` and `lint.yml` pass on the tip of `main`)
  and `preview.yml` (a preview of both Workers per pull request from a branch of this repo, uploaded with
  `wrangler versions upload --preview-alias pr-<N>`). Both build through `.github/actions/build-web`, which makes the
  snapshot too, cached on a hash of its inputs, and `scripts/smoke.ts` checks the result
  (`node scripts/smoke.ts [<site URL> <editor URL>]`; no URLs: production).

The workflows, secrets, one-time setup and the first deploy: [`../docs/deploying.md`](../docs/deploying.md).
`check-pytest` and `check-numeric` are run by hand. The Python suite is `.github/workflows/ci.yml`.
