## 2. Shape
Three kinds of test. (a) Pure-logic tests of the machine (machine.test.ts: a table of every state x event, scenarios, properties) and of helper modules (editor, files-ui, store). (b) Controller tests (app.test.ts) that wire the real `engine.ts`, `run.ts`, `files.ts`, `start.ts` onto a hand-written `FakeTransport`, fake store and fake lock. (c) Integration tests that run the real `worker.ts` in a Node worker thread (harness `nodeWorker`) with the real wheel, fake-indexeddb, and for some the Pyodide snapshot (engine, files, client, snapshot). Source-text tests: imports.test.ts and site.test.ts. Risk: app.test.ts (global singletons, 2.5k lines) and imports.test.ts (encodes the architecture as text counts). No view is tested at all.

## 4. Source-text tests (what they grep, what a harmless refactor does)

Rules in imports.test.ts. "Breaks" means fails on a restructuring that keeps behaviour.

1. Import-graph tests (lines 152-237): no view reaches `client.ts`/`worker.ts`; no `.tsx` imports `machine.ts` or `main.tsx`; `engine/` never imports `app/`; `.ts` does not import `.tsx`; `.ts` imports spell the extension; `src/site/` is isolated; the three HTML pages load only their entries; CSS `@import` isolation. Hard-codes the paths `src/engine/client.ts`, `worker.ts`, `machine.ts`, `src/app/engine.ts`, `RunControls.tsx`, `App.tsx`, `state.ts`. Breaks on a move or rename of any of them (the `reach(...).has(ENGINE)` sanity check names `src/app/editor/RunControls.tsx` and `src/app/state.ts`), and `views.length > 15` / `site.length >= 4` thresholds. All are Biome `noRestrictedImports`/`noRestrictedPaths`-like rules, except the transitive reachability one ("no view reaches client.ts through value imports"), which Biome cannot do; dependency-cruiser or a small script can. Replace most with a lint config, keep the transitive one in a test but with the paths in one constant block.
2. "TypeScript as Node runs it" (239-248): tsconfig flags and no JSDoc `@type {`. Harmless; the flags are checked by `tsc` itself (erasableSyntaxOnly makes it fail). The JSDoc grep could be a Biome rule or dropped.
3. "machine.ts is pure" (250-278): only type imports; a list of 11 forbidden names; no top-level `let/var`; exactly two ` as ` casts in the file and one in `transition()`. The exact-count of casts (2 and 1) breaks on any harmless edit that adds a cast or a variable named `signal`. Imports-type-only is `verbatimModuleSyntax` plus `noRestrictedImports`; forbidden globals is Biome `noRestrictedGlobals`; the cast count should go (replace with a code-review rule).
4. "ticket made in one place" (280-303): `as Ticket` occurs once in all of web/, in `machine.ts`, with the regex of the `mint` line; also no `as any|never` in all src and in machine.test.ts. A brand type already enforces most of this; the exact-text `const mint = (n: number): Ticket => n as Ticket;` breaks on a rename or a reformat of `mint`. Biome `noExplicitAny`/`noRestrictedSyntax` replace the second half.
5. "events get in through two doors" (305-351): the most brittle test. Counts `enqueue(` = 3, extracts the bodies of `dispatch`, `reply`, `connectEngine`, `enqueue` by their exact signature text (e.g. `"function dispatch(event: PlainEvent): Step | null {"`), asserts `queue = ` occurs once, `engineWriter` twice, `transition(` called once in all of SRC. Any rename, any signature change, any split of `src/app/engine.ts` (which the plan will certainly touch) fails it. It also asserts the single caller of `initial(` and `transition(`. This test must be rewritten (or deleted and its intent kept via a closure that is not exported).
6. "worker is posted to in one place" (353-363): `postMessage(` once in `client.ts`, in `#send(`; `#send(live, "mount"` etc. each once; `#send(live, "sync", undefined)` once. Breaks on any split of `client.ts`, or a rename of `#send`, or a new op with the same call shape.
7. "single instances" (365-395): `new EngineClient(`, `new Worker(`, `connectEngine(`, `connectFiles(`, `connectRun(`, `tabLock(`, `openStore(` occurrences per file; `open()` called once; definitions are `export function X(` in named files. Breaks on moving a definition between files (it pins `src/app/files.ts`, `src/engine/tab.ts`, `src/engine/store.ts`). Intent (main.tsx is the composition root) is a lint rule: `noRestrictedImports` of the constructors outside main.tsx.
8. "each signal has one writer" (397-452): which files name `engineWriter`/`graphicsWriter`/`runWriter`/`filesWriter`; lists every exported signal name as read-only or writable, and the count 13 of writable. Breaks on adding one writable view signal (the count), or on moving a writer object's owner. The read-only half is checked by the compiler (`ReadonlySignal`).
9. "no counter or flag outside the machine" (454-496): a blacklist regex of old names (`gen`, `attempt`, `was`, `taking`, `queued`, `onStatus`, ...) over all src, with a hard-coded allowed-file list of five files and equal-count assertions for each (`count(gone) == count(resetAt)`). It forbids any local variable called `was` or `attempt` anywhere in src, and pins that `worker.ts` has `const was = new Map(before.map`. Breaks on any rename or move; it is also a history test (names of removed code). Delete it and keep only the structural parts ("transport knows no state name", via the type of the transport).
10. CSS rules (498-536): `[data-engine]` selectors; every `:hover` is in `@media (hover: hover)`. Both independent of TS structure; the `:hover` one is a stylelint rule. The `[data-engine^="other-tab"]` check is brittle to CSS reorganisation but harmless.
11. `ignoreHeldEnter` (504-509): counts `onKeyDown={ignoreHeldEnter}` per view file (3, 3, 1). Breaks on any refactor of the buttons (a shared button component would reduce the count and fail this). It stands in for a missing behaviour test of the views.

Rules in site.test.ts that read text: (a) `language.ts` has `<prefix>: \d` for each OWN_PREFIX (line 75; breaks if the table is reshaped); (b) `src/app/env.ts` has `LANDING_URL = __SITE_URL__` and `banners.tsx` has `` BROWSERS_URL = `${LANDING_URL}#browsers` `` (lines 112-113; verbatim lines of two src files, breaks on any edit of either, including formatting); (c) theme: `theme.ts` has `saved.set("<KEY>"` (415; text, though the dynamic `import` of both theme modules above it is a real contract); (d) the editor path never spelled in the whole of src/scripts/e2e/workflows (177-245; a whole-repo grep, robust to moves and useful, but it is a lint rule); (e) clean-room greps of html and sample files (421-446; harmless, repo-level policy). The two lines under (b) are the ones that hit the audit.

Which rules would a restructuring of `src/app` or a split of `worker.ts`/`client.ts` force to be rewritten: 1 (paths), 5, 6, 7, 8, 9, 11, and site.test (b). A split of `machine.ts` rewrites 3 and 4.

## 5. harness.ts / node-worker.ts
- `nodeWorker()` runs the real `worker.ts` in a Node `worker_threads` Worker; node-worker.ts stubs `self`, `postMessage`, and either bridges the page's `FileStore` over a MessagePort (`takeAll`/`applyRun`) or loads fake-indexeddb. The design is good: tests exercise worker.ts, store.ts and client.ts together with no mock of them.
- Global state: `started` is a module-level Set of workers; every file must call `endWorkers` in `after` (a forgotten call hangs `node --test`). Each test file runs in its own Node process (node:test default), so state does not cross files. Inside app.test.ts state does cross tests: `S.*` signals, `engine`'s module state, `localStorage` replaced on `globalThis`, `<html>`/`document` fakes; reset by hand in `beforeEach` (lines 303-317) by listing the signals to clear. A new signal added to `state.ts` that is not in that list leaks between tests. Order dependence: files.test.ts has one 580-line test with nested `t.test` steps that must run in order.
- `refuseWrites`/`abortWrites` patch `IDBObjectStore.prototype` globally (restored by `t.after`); safe only because tests in a file run serially.
- Duplicated setup: engine.test.ts (lines 31-36) re-implements the wheel loading harness.ts already exports; sample-run.test.ts (24-28) does it a third time.
- Sleeps: `sleep(`/`setTimeout` counts per file: app.test.ts 14 (+ `tick() = sleep(0)` used everywhere as "let microtasks drain"; `heard()` = `sleep(70)` waits for the live-region window), client.test.ts 16, files-ui.test.ts 6, files.test.ts 5, engine.test.ts 4, sample.test.ts 4, harness.ts 2 (fakeWorker's `setTimeout(...,1)` answers; `sleep` itself), imports 1, editor 1, wakelock 1. About 55 in total. app.test.ts also has 19 `mock.*` uses and uses a simulated clock for the Break timer only in one test. Polling loops (`waitFor`/`while`): app 7, client 3, files-ui 5 (not inspected individually). The `sleep(70)` in `heard()` and `fakeWorker`'s 1 ms timer are timers standing in for events and are the likely flaky points (a 2-hour comment in test-map.md "Known flaky tests" is the e2e side; see that section).

Size M, risk low, and it should be done before the source refactor so the split follows the current boundaries.

## 11. Redesign question
No structural change to the tests. One structural thing around them: move the architecture rules out of `imports.test.ts` into tools made for them (Biome restricted imports, or dependency-cruiser) and keep only an import-graph reachability test with the paths in one place. Cost M; it removes the part of the suite that will fail hardest on the planned refactor and gives no information about behaviour. I would do it before the refactor.

## 12. What is good
machine.test.ts (table, scenarios and properties over the pure machine, and the SPEC-matrix comparison) is the best net the audit has: it lets the machine and the transport be restructured safely. The real-worker harness (`nodeWorker` with a store port) tests worker/store/client together without mocks. The drop-record assertion in app.test.ts (`expectDrops`) catches stale-event bugs in any controller change. Keep all three.
