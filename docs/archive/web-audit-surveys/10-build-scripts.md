## 2. Shape
`urls.ts` (addresses, ports, folders) feeds `vite.config.ts`, `playwright.config.ts`, `together.ts`, `smoke.ts` and `check-sizes.ts`. `build-id.ts` (inputs, build id, staleness) feeds `start-files.ts`, `vite.config.ts` and `check-snapshot.mjs`. `site-pages.ts` fills `{{tokens}}` and builds the commands lists and `_headers`.
Snapshot tooling is a cluster of untyped `.mjs` programs (make/check-snapshot, check-pytest, check-numeric, measure-startup) over `install-engine.ts` and `snapshot-node.ts`.
`vite.config.ts` is the highest-risk file: it holds two builds, two dev servers and two preview servers in one default export, and runs file-copying side effects when it loads. `make-snapshot.mjs` is second (a 290-line top-level script with embedded Python).

## 4. Candidate work items
1. **Type-check the tooling.** Add `vite.config.ts`, `playwright.config.ts`, `e2e/`, `scripts/` to tsconfig `include`; rename the `.mjs` scripts to `.ts` (they already import `.ts`) and fix what surfaces. Size M (the fixes are unknown; maybe 10-40 errors). Risk low. Tests that catch: `npm run check`; none run the scripts, so smoke each by hand (`check-snapshot --cases x`). Land first, before the other script changes.
2. **Shared script helpers.** One `scripts/lib/` with `arg`, `repo`, the shard pool (`runShards(items, spawnChild, timeout)`), `bootPyodide`, and one `wheels()` that `build-id.ts`, `install-engine.ts` and the config use. Size M. Risk low-med (the three check programs). Tests: none automated; `npm run check-snapshot` and `check-numeric` runs by hand (about 4 min each). Needs item 1.
3. **Split vite.config.ts.** Move plugins to `scripts/vite/` (`sitePages`, `siteFiles`, `startFiles`, `headers/isolate/slash`) and the config to a thin file that composes `site()`, `editor()`, `preview()`. Move the wheel and runtime staging into a plugin's `buildStart` or `configResolved`, not module load (F2). Size M. Risk med. Tests: `test/site.test.ts`, `test/build-id.test.ts`, e2e (a full `npm run build:local` plus `playwright` are the real guard). Needs item 1.
4. **Decide on `DOFILE_EDITOR_BASE`.** If nobody deploys the editor under a path, delete the branches (F3) and the tests that cover them. Size S-M. Risk low; `test/site.test.ts`, e2e `sample.spec.ts` and `landing.spec.ts`. Maintainer decision first.
5. **Record all snapshot inputs.** Put the env-driven knobs in the manifest, have `staleness` compare them (or have deploy refuse a quality below 11), and generate the cache key and the ENGINE regex from one list in `scripts/`. Size S. Risk low. Tests: `test/build-id.test.ts`.
6. **Make `commands` and `wheel` safe.** Write to a temp file then move; make one `wheel` call per `e2e`; check byte-identity of the wheel (F9). Size S. Risk low. CI diff catches a bad `commands.json`.
7. **Replace the browser.py regex** with a generated `denied.json` written by the same `commands` script (or into `commands.json`), and import `OWN_PREFIXES` from `src/stata/language.ts` (it imports nothing from the editor). Size S. Risk low. `test/site.test.ts`.
8. **Move or drop `measure-startup.mjs`** (to `docs/` tools, or delete if the plan no longer uses it) and fold `compare-pytest.mjs` into `check-pytest`. Size S. Risk none to the product.

## 5. Redesign question
Yes, one: a plain build contract. Make the editor's inputs (wheel, extra wheels, Pyodide files, snapshot) a staged `public/` made once by a script, `npm run stage` (or the one `wheel` script), and let `vite.config.ts` only read it. Today the config stages files while loading, so every `vite` command depends on the wheel, and the snapshot, the dev warning and the build fail all re-derive staleness from `inputs()`. Cost: roughly M; it changes `package.json`, `build-web` and web.yml. It would break the "one command" feel of `npm run dev` unless `dev` and `build` call `stage` first (they already call `wheel`). I would do it together with item 3, not alone. The rest of the structure (one `urls.ts`, one `staleness`, one `start-files.json`) is sound.

## 6. What is good
- `urls.ts` is the single owner of addresses and ports (CLAUDE.md claim holds).
- `staleness()` is one function used by the config, the dev warning, `check-snapshot` and the CI cache step.
- `start-files.ts`, `site-pages.ts`, `build-id.ts` are pure, typed and unit-tested.
- Fail-fast checks (`URLS_MISSING`, the editor-folder guard, size check).

## Scripts reachability, CI vs local, static pages, generated files
- **Not reached by package.json or a workflow**: `compare-pytest.mjs`, `measure-startup.mjs`, `compare_numeric.py`, `numeric_probe.py`, `pytest_report.py` (the last two are called by the check scripts). README documents all of them (README.md:77-82, 95, 174 "run by hand"). Confirmed.
- **Dependency sketch**: `e2e` -> `snapshot` (-> `wheel`) -> `build:local` (-> `build` -> `wheel`, `vite build`, `vite build --mode site`) -> playwright (webServer = two `vite preview`). `deploy` -> `lint:strict`, `snapshot`, `build` (production), `check-sizes`, two `wrangler deploy`. `dev` -> `wheel`, `build-id.ts --warn`, `together.ts dev`. `cf:dev` re-spells a build command line (`DOFILE_SITE_URL=... npm run build`).
- **Hidden work**: `wheel` deletes `../dist/dofile-*.whl`; the config writes `public/`; `commands` and `sample` write into `src/`.
- **Generated and committed**: `src/stata/commands.json` (`npm run commands`; CI re-runs it and `git diff --exit-code`), `src/app/sample-files.ts` (`npm run sample`; `test/sample.test.ts` compares). `public/*.whl`, `public/snapshot/`, `public/pyodide/` are gitignored. `wheels/pyreadstat-*.whl` is committed (by hand: build.sh).
- **CI vs local**: workflows mostly call the same npm scripts (`check`, `test`, `build`, `lint:strict`, `e2e`, `snapshot`, `check-snapshot`). The re-spelled parts: web.yml's commands-diff step, and `build-web` which runs `npm ci && npm run wheel`, the cache test `node scripts/build-id.ts`, then `npm run build && node scripts/check-sizes.ts` (`npm run deploy` spells the same chain a second time in package.json). `smoke.ts` is called by deploy.yml and preview.yml. `build-web` is shared by deploy and preview (no duplication there).
- **Static pages**: orderly. 13 `{{tokens}}` across three names in landing.html, 3 in commands.html, two plugins (`sitePagesDev`, `sitePages`) and `site-files`; `src/site/` is 140 lines of TS. Not a template engine; keep.
- **Main chunk**: `main.tsx` imports `App.tsx`, which statically imports every view (Editor, LogView, DtaView, FullSize, DataTab, GraphTab, ResultsTab, all dialogs and banners). No `lazy()`, no `Suspense` anywhere; the only dynamic import in `src/app` is `kblog.ts` (main.tsx:50). Likely content (guess, no build run): CodeMirror (`@codemirror/view`, `state`, `language`, `lang-json`, `lang-markdown`, `codemirror` minimalSetup, `@lezer/highlight`), at a guess more than half of the 562 kB, plus Preact, signals and the app. `brotli-wasm` and `pyodide` are in the worker bundle (`inlineDynamicImports`), not here. A `lazy()` split of the output tabs or dialogs saves little (the editor and CM are needed at first paint). The cheap options: dynamic-import `lang-markdown` and `lang-json` via the existing Compartment in `cm.ts` (about 20 lines), or raise `chunkSizeWarningLimit`; `manualChunks` for vendor only helps caching. Preact's `lazy` lives in `preact/compat`, which the app does not use.
