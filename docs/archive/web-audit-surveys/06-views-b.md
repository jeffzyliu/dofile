## 2. Shape
Views hang off two registries (`DialogHost`, `BannerSlot`) and a small ui/ kit (Menu, Dialog, Tablist, Live, focus-hooks). Output tabs are views over pure `format.ts` plus signals in `view.ts`. Focus is placed by "the owner asks by signal, the target focuses itself in a layout effect" (`useFocusRequest`). Risk concentrates in two files: **FilesPane.tsx** (view, tree state, rename/draft state machine, drag-drop, menus all in one module with module-level state) and the **focus hand-off web** (`Dialog.tsx`, `states/focus.ts`, `Menu.tsx`, `EditorTabs.tsx`, `FullSize.tsx`), which depends on ordering that only comments and e2e hold.

## 5. Redesign question
Cycles: `dialogs.tsx` imports its 8 views (value imports); each view imports `DialogOf` from `dialogs.tsx` (`import type`), so view -> registry -> view. Same for `banners.tsx` (6 views; 1, 5, 6 in madge) and `BannerSlot`. All 7 are type-only and erased at build. A cycle-free shape: the registry imports views, views import only `types.ts`, where `Dialog`/`Banner` already are. (The census's other 3 cycles, files.ts/sample.ts/open.ts/run.ts/engine.ts, are real value cycles in controllers, not here.)
Structure: mostly sound; tidy it. The one change worth doing is item 4's principle: logic currently in .tsx (rename machine, matrix reader, dta reader, drop state) belongs in .ts controllers, which web/CLAUDE.md already requires and Node can test. Cost M-L; breaks nothing if files.spec stays green. A focus-target registry (owners register "tree", "tabs", "more-actions") would remove F3 but costs more and I would do it only after FilesPane is split.

## 6. What is good
`useFocusRequest`: the owner draws, the target focuses in its own layout effect. `format.ts` is DOM-free, pure, has 15 Node tests; ResultsTab and DataTab are NOT two copies of one table (grid markup is shared in spirit only: MatrixGrid vs Browse). The typed mapped-record registries make a missing kind a compile error. `words.ts` plus states.test.ts is the right pattern for text. Menu's index-based active item is carefully reasoned.
