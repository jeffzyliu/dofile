dofile web demo: user flows

Deliverable 2 of the UI/UX design step (docs/design/README.md). Seven flows, each a trigger, the steps (what you do, what the page shows, what the engine's Web Worker does), the branches, and where it ends. Every step is tagged with what the proof-of-concept page does today, with the line that does it, or what is still to build. The wireframes and components come from these steps and from the list of states and messages at the end.

Branches

#YouThe page showsThe engineState

  • Data kept, as the last complete command left it.
  • nowclient.js:83–85

B. One long command does not stop in 5 s

  • nowmain.ts:78

Decisions (2026-11-08)

Panels

  • Files, editor (tabs for several open files), log with a one-line command line under it (up and down arrows recall earlier commands; output goes to the same log).
  • Graph: one panel showing the latest graph, the session's earlier graphs as thumbnails; the log links "graph 2" where each was drawn. A .png opened from the files shows there too.
  • Data: a header (observations, variables, file name, size, memory), the variables (name, label, type; filter; a click marks the variable's column in Browse, and inserts nothing: iteration 2), and Browse (the first rows: needs the engine addition).
  • Results: e() and r(), in the MCP server's format, then the locals and globals (internal temporary names hidden).
  • Scope: a whole-file run starts with no locals, as a do-file in Stata, so running a file twice gives the same answer; a selection and the command line keep the locals of the runs before them. Globals, data and e()/r() carry over. The log explains, in our words, a restore with nothing preserved (preserve ends with each run) and a temporary name whose variable or file is gone.
  • Help: OpenDTA's own help pages (MIT, written in its own words; every one of the 515 commands has a topic). help regress opens the page here, not in the log; "Also see" links work. No links to Stata's manuals.
  • No history panel in the first version: the log has "next error", the editor marks error lines.
  • Phone: tabs (Files, Editor, Log, Data, Results); the wireframes try two desktop arrangements.

Behavior

  • Explicit Save, as now, plus an unsaved draft kept in the browser's storage.
  • The last log is kept across a reload; "Download log".
  • A second browser tab says dofile is open in another tab and offers to take over.
  • Opening a file: .png in the graph panel, .csv as text, .dta shows its variables and offers "Load it" (use).
  • Name clashes: Keep mine (the default; Enter keeps this one, Esc keeps yours for all the rest) or Replace with uploaded, plus "Do the same for the other N clashes" (iteration 2).
  • A zip with one top folder keeps it.
  • Landing page wording: your files and data never leave the browser (the runtime itself comes from a CDN).
  • "Delete all files" in the file panel's menu, with a confirmation.
  • Memory in the status bar, a warning near a per-device limit (a guess until measured).
  • Sharing a do-file by link: later.

Decisions (2026-11-09, iteration 2 of the hi-fi mockups)

Running

  • Run and Run selection send a copy of the editor's text, saved or not; editing during a run doesn't change it.
  • do and include read the saved file; the log notes when it is open with unsaved edits.
  • Each run's output starts with a line saying what ran and whether it started with no locals (shown only).
  • The ⌘ ↩ chip is on the button it triggers. Phone: Break takes Run's place, looks different, ignores taps for 600 ms.

Start-up

  • First visit: ask before downloading the engine; the same dialog shows the download bar and the stages.
  • Not now: an editor and file manager, with a banner to download later (needs the page to read IndexedDB itself).

Files and panels

  • Per-file ⋯ (and right click): Open, Rename, Download, Delete. "Download all (.zip)" under the file list.
  • Reset asks first. Help from the editor's context menu.
  • Data: a click marks the column in Browse; nothing is inserted.

Decisions (2026-11-09, iteration 3)

Break and start-up

  • Break's countdown: "Don't reset: wait for it" cancels the 5 s timer; the Break lands at the next safe point; while it waits, Break becomes "Reset now".
  • The download can be stopped; after Not now, Run opens the download prompt.

Files

  • Name clash: Enter keeps this one; Esc keeps yours for all the rest.
  • Storage not kept: a notice with Download all when persisted() is false.

Running

  • A selection run warns about a local it uses that isn't set yet.
  • The temporary copy Run sends is never named in the log.

States and messages the design must show

Engine

  • starting, with the stage (4 stages)
  • ready
  • running, with elapsed time
  • memory use, and a warning near the limit
  • breaking, with the reset countdown
  • stopped by Break (rc 1, data kept)
  • reset (rc 9998) with its reason: Break did not stop it, it crashed, you pressed Reset
  • failed twice: reload the page
  • did not start: files still available
  • not cross-origin isolated: Break resets

Files

  • open, unsaved, saved, could not save
  • uploading (count), uploaded, replaced the open file
  • name clash: Overwrite / Keep existing / Overwrite all; zip entries refused
  • commands the uploaded do-files use that dofile lacks
  • a drop target while dragging
  • new or changed by the last run
  • not UTF-8: cannot open in the editor
  • confirm delete; name already exists; restore the sample
  • storage: kept or not kept by the browser; too big (unknown limit)

Log

  • command echo, output, table
  • error line with rc, linked to its line in the editor
  • path-mapping note
  • unknown (community) command, explained
  • graph, inline
  • Break line; reset notice with "Run the file again"
  • a help page (in the Help panel); no topic found (if, foreach, forvalues today)

Possible engine additions (not decided)

  • return the first rows of the data (for a data view; today only the variables: data_summary())
  • decided: report memory use, to warn before a phone runs out (the worker's memory and the dataset's size)
  • decided: unpack a .zip and make one of the folder (F3, F7), in the worker
  • decided: a whole-file run starts with no locals (an option on Engine.run; MCP unchanged)
  • decided: list the locals and globals for the Results panel
  • not the engine: commands the engine lacks are found by the editor's own tokenizer (F3 3a, F4 1a)
