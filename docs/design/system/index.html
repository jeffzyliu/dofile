dofile design system

Deliverable 5 of the design step (docs/design/README.md). The tokens are web/src/styles/tokens.css, the one source for the page and the design pages; the components are web/src/styles/ui.css, which the page takes over in steps 6 and 8. This sheet shows each component in its states; the mockups show them in place. It follows the system's light or dark setting; ?theme=light or ?theme=dark forces one. Checks: npm run contrast, npm run fonts, npm run axe, npm run tabwalk (from web/).

Color

    Rules. Text is at least 4.5:1 on its background, and control edges, the focus ring and bars at least 3:1, in both themes (contrast.mjs lists every pair in use). --border is for dividers only, never a control's only edge. Meaning is never color alone: errors also say r(111) and carry a bar; warnings an icon or a wavy underline. Graphs are PNGs with their own light colors, so they sit on --graph-card in both themes (a dark plotting style is planned). Syntax colors are the accent (commands), green (strings), purple (macros), muted (comments); no italics are loaded, so comments differ by color only. Forced colors (Windows High Contrast) replace every color and drop backgrounds and shadows: the end of ui.css redraws icons, dots, marker bars, the progress fill and the focus ring in system colors, and the error line in the highlight pair. Check with shot.mjs --forced.

    Fonts. IBM Plex Sans for the interface, IBM Plex Mono for code, the log and the wordmark. Only Sans 400/600 and Mono 400/700 are loaded, so bold is --w-bold-ui (600) in Sans and --w-bold-mono (700) in Mono; font-synthesis: none stops the browser faking others (fonts.mjs checks every text node). Line height --leading 1.5; the log fits 80 columns in about 600 px. Plex lacks ⌘ ▶ ■ ▾ ● ⋯: those are SVG icons.

    Shape and depth

    --radius-sm 3 px (chips, badges, small buttons inside rows), --radius 4 px (buttons, inputs, banners), --radius-lg 8 px (panes, dialogs, menus, toasts). --bar 3 px: the marker on a row's left edge (the open file, a running line, an error line, a picked variable). Only floating things have a shadow (--shadow-menu, --shadow-dialog); panes are flat with a 1 px --border. --scrim is black at .32 (light) or .55 (dark). --focus: a 2 px accent ring with a 2 px gap; inside panes that clip, a 2 px inset ring.

    Icons

    Our own 16 px SVG shapes, drawn as masks so they take the text color: play, stop, fold open, fold closed, more, theme, graph, file, check, warning. An icon alone always has an aria-label on its button.

    Toolbar buttons

    Kinds. One primary per view (Run, or a dialog's default). Default for the rest. Quiet for secondary dialog actions and icon buttons. Stop is Break: outlined and disabled when idle, filled red while running; on a phone it takes Run's place and ignores taps in its first 600 ms. Hover is a step darker (lighter in dark mode: --surface-2, --accent-hover, --error-hover) and a press moves the button down 1 px; disabled buttons have neither. Disabled is --disabled-opacity; a button that is busy (Run while running) is aria-disabled, not disabled, so focus stays on it. The key chip sits on the button its keys trigger, ⌘ on a Mac and Ctrl elsewhere; disabled buttons show none. The theme button cycles System, Light, Dark. The unsaved dot has a label for screen readers.

    Pane, tabs, file list

    Log

    Log lines, top to bottom: the head (banner and version; shown only, never in a saved log), the run-head (UI font, what ran and what it starts from, with a run warning when a selection uses a local nothing has set), the echo of each command (bold), plain output, a note (muted), the error line (red, bold, never color alone: it says the message and r(111)), the hint under it (muted, its labels in ink), and Go to line, which moves the editor. The log is role="log"; Mono at --log, 80 columns, no wrapping. The command line runs one command as if typed, with ↑ ↓ history.

    Status bar. Idle (green dot, Ready, the last run's result) and running (accent dot, what runs, a timer). It is not a live region: state changes are said once by a hidden role="status" region.

    Banner. Inside a pane, above its content: info (accent), warning and error (each with the warning icon, so they differ from info without color, as in Windows High Contrast). It stays until its cause goes away or it is dismissed, and may hold buttons.

    Saved analysis.do

    Toast: a short confirmation that asks nothing: "Saved analysis.do", "Copied", "3 files uploaded". Inverted colors (--surface on --ink), bottom center above the status bar, one at a time, 4 s (longer while hovered), no motion with reduced motion. No buttons: anything to act on, or to read twice (the upload report, a reset), is a banner or a dialog. It never takes focus, and the hidden live region says the same words. Approved 2026-11-09; no mockup draws it yet.

    Dialog, menu, progress, empty state

    Delete clean.do?

    It is removed from this browser. This can't be undone.

    Dialog. Centered over the scrim (a bottom sheet on a phone), --shadow-dialog, a title, plain sentences, actions on the right. Focus starts on the safe choice (Cancel for Delete and Reset; the default otherwise); Esc cancels; focus returns to what opened it.

    Menu. From a ⋯ or a right click; items are buttons with role="menuitem", arrows move, Esc closes. Hover is the soft accent, a key hint on the right, a destructive item in the error color with an ellipsis when it asks first.
