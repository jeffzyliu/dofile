# Formatting and linting: Biome for the web code, ruff for the Python code

Status: **decided and done (2026-11-11), merged by pull request #13**; it was done on the branch `prototype1-step3`, on top of
prototype 1 step 3.5 and before the merge and step 4. The first version of this file proposed to wait for the merge and to use a width of 160; the measurements
below changed both.

## Why

- Nothing formatted or linted the code. `web/` had `tsc --noEmit` only; Python had nothing. The only linter was actionlint
  for the workflows.
- The code was formatted by hand and the styles differed, so layout-only edits showed up in diffs and the code was hard to
  review.
- Agents write most of the changes. With a formatter, layout stops being a decision and diffs show only real changes.
- It is done now because step 4 is next, is nearly all web code and is split into parts: a reformat after those start
  conflicts with each of them.

## Decisions

| Subject | Decision |
|---|---|
| Tools | Biome 2.6.6 for `web/` (format, lint, import sorting); ruff 0.17.4 for dofile's own Python. Both pinned exactly; bump on purpose. |
| Line width | 120 for both. The docs and comments are written to about 120, and neither tool rewraps comments. |
| Style | Each tool's defaults (Biome: 2 spaces, double quotes, trailing commas; ruff: its defaults). |
| CSS | Formatted by Biome (one declaration per line). |
| Aligned trailing comments | Not kept: there were 412 in 47 files, too many to mark one by one. |
| Lint rules, web | Biome's `recommended`, with six rules off (below: `biome.json` cannot hold comments). |
| Lint rules, Python | ruff's defaults (in 0.17 a broader set than `E4, E7, E9, F`: import order, unused `noqa`, and more). No rule is off. No separate list of warnings. |
| Errors and warnings | A lint **error** blocks the dev server (an overlay over the page), a build and `npm run check`. A **warning** is allowed while developing, and fails a pull request, a push to `main` and a production build (`npm run deploy`). A finding is fixed or its rule is turned off, with the reason, before a merge. |
| Markdown, YAML | Not formatted. (ruff does check Python code blocks in Markdown; none needed a change.) |

## Rules turned off in `web/biome.json`, and why

| Rule | Findings | Reason |
|---|---|---|
| `style/noNonNullAssertion` | 183 | `x!` is used on purpose under `strict`; a style choice, not a bug class. |
| `suspicious/noExplicitAny` | 28 | Pyodide's objects, caught errors and test doubles; `tsc` is strict where it matters. |
| `style/noDescendingSpecificity` | 23 | The CSS is ordered by component, not by specificity. |
| `suspicious/noTemplateCurlyInString` | 6 | `"${name}"` in a plain string is deliberate: Stata's global macros, and source text the tests scan. |
| `suspicious/noConfusingVoidType` | 7 | The `Ops` table (`src/engine/types.ts`) writes `void` for "no arguments" and "no result", as SPEC section 6 does. |
| `complexity/noImportantStyles` | 2 | Both `!important` are deliberate: the `[hidden]` override and `.visually-hidden`. |

To turn a rule back on, fix or ignore its findings in the same commit.

## Scope

- **Biome** (`web/biome.json`): everything in `web/` that Biome knows (TypeScript, TSX, `.mjs`, JSON, CSS), except
  `dist/`, `public/`, `wheels/`, `test-results/`, `.dofile/`, the fonts and `src/stata/commands.json` (generated by
  `npm run commands`, and CI compares it with what is committed). The scripts in `docs/design/` are outside `web/` and are
  not covered.
- **ruff** (`[tool.ruff]` in `pyproject.toml`): `src/dofile/`, `tests/`, `scripts/`, `web/scripts/*.py`.
- **Never formatted:** `src/dofile/_vendor/`, `tests_opendta/`, `legacy/`. The vendored engine is never edited by hand, and
  the vendor script's patches apply to upstream's exact text.

## What was measured (before the decision)

On a copy of `web/` at step 3.5 (11,844 lines of TypeScript, TSX and `.mjs` in 79 files), Biome 2.6.6:

| Width | Files changed | Lines added / removed |
|---|---|---|
| 100 | 69 | +10,533 / −3,490 |
| 120 | 68 | +8,137 / −2,985 |
| 140 | 65 | +6,632 / −2,629 |
| 160 | 65 | +5,770 / −2,387 |

The width is not what makes the diff: Biome's fixed rules are (a one-line interface or object is expanded, a union and
`case` labels go one per line, aligned comments collapse). So the width was chosen for reading. `ui.css` goes from 415 lines
to about 1,500. Python at 120: 27 of 28 files, +1,355 / −524.

## Commits, in this order

1. **Config, no code change:** `web/biome.json`, the pinned packages, `npm run format` and `npm run lint`; `[tool.ruff]`,
   ruff in the `dev` group, `poe format` and `poe lint`.
2. **Biome reformat only** (`npm run format`: layout and import order, nothing else).
3. **ruff reformat only** (`poe format`).
4. **`.git-blame-ignore-revs`** with the hashes of commits 2 and 3, so `git blame` skips them. GitHub reads the file by
   itself; a clone needs `git config blame.ignoreRevsFile .git-blame-ignore-revs` once.
5. **Lint fixes**, one commit: every finding fixed with no change in behavior, or its rule turned off with a reason. A
   finding that is a real bug is reported and gets its own commit and test.
6. **The gates and the docs:** `npm run check` runs Biome before `tsc`; the Vite plugin (`vite-plugin-checker`) shows lint
   errors over the page in development and fails a build; CI; `CLAUDE.md` and `web/CLAUDE.md`.

The gates come last so that no commit before them has a build that its own rules refuse.

## Commands

| Where | Command | Errors | Warnings |
|---|---|---|---|
| Development (`npm run dev`) | the Vite plugin runs `biome lint` on each change | overlay over the page | listed |
| Local check | `npm run check` (`biome check`, then `tsc --noEmit`); `uv run poe lint` | fail | listed (Biome) |
| Local build (`npm run build`) | the Vite plugin | fail | listed |
| Pull request, push to `main` | `biome ci --error-on-warnings` (`web.yml`); `poe lint` (`ci.yml`) | fail | fail |
| Production (`npm run deploy`) | `biome ci --error-on-warnings` first | fail | fail |
| Fix the layout | `npm run format`; `uv run poe format` | | |

CI cannot refuse a direct push to `main`, only mark it failed; branch protection (a pull request with `web ok` and `ci ok`
required) is what refuses.

## Agents

- Format at the end of a task or before a commit, not after every edit: a formatter that runs between an agent's read and
  its next edit can make the edit's text stop matching.
- Never run a formatter on `_vendor/` or `tests_opendta/`.
- An ignore comment (`// biome-ignore ...`, `# noqa: ...`) always names the rule and gives the reason.

## Reviewing the unpushed work

Nearly all the code since `origin/main` is new (66 files added, 6 renamed, 10 deleted, 20 modified), so a diff against a
formatted copy of `origin/main` is useful only for the 20 modified files. The rest is read whole, formatted, at the tip, in
the order of `web-engine-data-flow.md`.

## Risks, and what answers them

- **A large, noisy commit:** commits 2 and 3 change layout only, and `.git-blame-ignore-revs` hides them.
- **Behavior:** `npm run check`, `npm test`, `uv run poe ci` and the e2e run pass after the reformat as before it. Formatting
  `src/dofile/` changes the wheel, so the snapshot is rebuilt (the e2e run does it).
- **Type-only syntax:** Node runs the `.ts` files with the types removed; `tsc` still enforces the erasable-syntax rules
  after Biome's import sorting.
- **Biome is not Prettier**, and has fewer lint rules than ESLint. If an ESLint-only rule is needed later, add ESLint for
  it and keep Biome for formatting. Oxlint beside Biome for type-aware rules is a separate, later decision.

## Done when

- `npx biome ci --error-on-warnings` (in `web/`) and `uv run poe lint` pass on a clean checkout, locally and in CI.
- `npm run check`, `npm test`, `uv run poe ci` and the e2e run pass.
- `.git-blame-ignore-revs` lists the two reformat commits.
- `CLAUDE.md` and `web/CLAUDE.md` name the commands and no longer say there is no formatter.
