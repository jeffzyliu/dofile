# Test map

What the tests are for, by function. This map describes scope, not numbers: it keeps no counts, so a branch that adds a
test does not conflict with another. Web counts: `cd web && npm run test-counts` (per file and in total; the script's
header says how to get the e2e skips). Python counts: `uv run pytest --collect-only -q tests | tail -1` for dofile's own
tests (the "deselected" part is the slow Stata comparison; `-o addopts=` counts it too, `-m slow` only it) and
`uv run pytest --collect-only -q tests_opendta/tests | tail -1` for the vendored suite.

- [Python](#python): dofile's own tests, the conformance corpus, the vendored OpenDTA suite.
- [Web](#web): unit and integration tests on Node's test runner (`node --test`), Playwright end-to-end tests.
- [Running them](#running-them).

## Python

| Part | Where |
|---|---|

`tests_opendta/` is regenerated by `scripts/vendor_opendta.py`; don't edit it.

### dofile's own tests, by function

**1. Engine adapter** (`test_engine.py`)
- Result shape: log, rc, `results()`, `r(table)`, the e_changed and r_changed flags, JSON for missing values and
  matrices.
- Error containment: a Python exception is rc 9999; a MemoryError or a full WebAssembly heap is r(909) after
  `on_memory_error`; a crash inside a program closes its scope; each call is a do-file scope.
- Regression tests for OpenDTA fixes (`test_odtN_*`, with the patches in `scripts/patches/`); Stata expressions cannot
  reach Python.

**2. Engine features added for the web demo** (`test_engine_web.py`)
- Output streaming (`on_output`); error line numbers, including nested, included and earlier-run programs.
- Which command made each graph, and the dark plot theme; `describe_file`, `fresh_locals`, memory size.

**3. Interrupt and Break** (`test_break.py`; also the timeout and cancel tests in `test_worker.py`)
- A Break stops between commands and keeps the data; loops stop between passes.
- A command with no safe point is ended with rc 9998.

**4. Log cutting** (`test_log_cut.py`): the biggest blocks go first, short results survive, and the cut is fast.

**5. Sandbox and security** (`test_sandbox.py`; also parts of `test_engine`, `test_worker`, `test_mcp`)
- Denied commands return rc 199.
- Reads and writes outside the allowed folders are blocked; symlinks cannot leave the workdir.
- The audit hook blocks network access and subprocesses.
- Unsafe mode over HTTP is allowed only on loopback.
- Each case runs in a subprocess, because audit hooks cannot be removed.

**6. Workers and pool** (`test_worker.py`)
- State persists between calls; dead or failed workers are reported, then restarted; forkserver use.
- The pool isolates sessions, evicts only idle ones, reaps, and refuses when all are busy.

**7. MCP server** (`test_mcp.py`)
- Transports: real stdio and real HTTP, session tokens and expiry.
- Tools: `get_matrix`, `get_file`, `describe_data`, upload tokens (single-use, expiring), `reset`.
- Concurrency: queueing, cancel races, no leaked threads.
- The advertised schema and `MCP-SCHEMA.md` name the same fields.

**8. CLI** (`test_dofile_cli.py`): exit codes, log and JSON output, nested do-files, `$` and backquotes in paths.

**9. Browser and Pyodide shims** (`test_browser.py`, `test_pathshim.py`, `test_linalgshim.py`)
- The browser entry point's JSON API, and the ballast the memory cap relies on.
- Break: a SIGINT while no run is busy (the top or the end of a run, between runs) is put back, not dropped, and stops
  nothing by itself.
- Mapping of foreign paths; the `numpy.linalg` shim.
- Guards: the web highlighter's command list matches the engine, and no new path sites appear in the engine.
- The lazy graphics part (two tests): a graph waits for it, and a Break or a failure stops only that graph; the run's log
  so far reaches the page before the graph waits.

**10. Packaging** (`test_version.py`, `test_vendor.py`, `test_sample_data.py`)
- Version stamps, the `MCP-SCHEMA.md` version line, the vendor stamp; the patched vendored package has no undefined
  names (the vendor script's ruff F821 check).
- The web demo's sample dataset (`web/sample/data/wages.dta`) is what `web/sample/make_sample.py` makes, byte for
  byte, and two builds make the same bytes (its `--check`).

**11. Correctness against references** (`test_conformance.py`)
- The `CHECK name=value` lines of the corpus files must match `data/ref.json` to 1e-6 relative. The values come from
  statsmodels and linearmodels, not from OpenDTA.
- The probes (`probe/*.do`) must run with rc 0.
- Known gaps are `xfail(strict=True)`: `reghdfe`, `esttab` and `outreg2` (GAP-1, community commands).
- `test_sandbox.py::test_corpus_and_probes_still_work_under_sandbox` runs the same corpus with the sandbox on.

### Vendored OpenDTA suite, by function

These test the Stata-language engine itself. Grouping is by file name.

- **Statistics and estimation** (the largest group): basestats, estimation, stats, vce, anova_estat, nptests,
  survival(2), timeseries,
  irf, multivariate(2, block, a), multilevel(1-3), panel_block, sem(2), gsem, irt, mi(2), svy(2), bayes, power(1-3),
  `models_block*`.
- **Data management**: data, datamgmt, datamgmt_options, egen, combine, sample, replace_ts, datatools,
  codebook_bootstrap.
- **File I/O and formats**: dta, delimited, excel, infile, formats, storage.
- **Language and programming**: language, lexer, expr, programming, programs, macrofuncs, matrix, mata, mata_classes, classes,
  vector_functions, superscript.
- **Graphics**: graphics.
- **Epidemiology tables**: epitab.
- **Robustness and tooling**: rng, numerics, hints, i18n, guard, logs, cli, compare_tool, updater, comandos,
  partial_features.
- **Stata 14 reference logs** (slow): each `.do` file's output is compared with a log made by real Stata 14. The logs
  are not distributed (see `LICENSE-POLICY.md`).

## Web

### Unit and integration (`node --test`, `web/test/`)

Node runs the `.ts` files as they are (`npm test`); there is no Vitest or Jest. Several files make their tests in a
loop, so a file has more tests than `test(` lines; `npm run test-counts` counts what the runner reports.

- `wiring.ts`: not a test file: the stand-in transport, store and tab lock, the wiring of the controllers, and
  `resetState()`, which every `app-*.test.ts` runs before each test (through `useWiring()`): every writable signal of
  `state.ts` back to its value at load (found by shape, so a new signal is reset too), the controllers' own state, a new
  wiring, and the drop record checked at the end of each test. It makes the localStorage stand-in before it imports the
  controllers.
- `app-engine.test.ts`: the engine controller (`app/engine.ts`).
  - Start, Break, reset, crash; the download dialog; the cross-tab lock; stale replies; the race scenarios; a second
    `connectEngine` releases the earlier wiring's handles (download, graphics subscription).
  - No engine: a run or command is refused.
- `app-run.test.ts`: the run controller (`app/run.ts`): log, history, graphs, rows, toasts, banners.
  - "Clear log" and `canClearLog`; no engine: a command is refused and stays out of `history`; a run's promise settles when
    the after-run work throws.
- `app-files.test.ts`: the files controller (`app/files.ts`): the storage banner, a run that rewrites an open file
  (`ranOver`, the run-changed banner), Download all, `persisted`.
- `app-theme-tabs.test.ts`: the theme button and `applyTheme`; `setDirty`; strict UTF-8 (`decodeText`).
- `app-dta.test.ts`: `readDta` (`app/output/dta.ts`): one describe_file per .dta file and version, even when its tab is mounted again
  while the first is pending; a failed call is asked again.
- `app-viewport.test.ts`: the phone keyboard (`app/viewport.ts`): Safari's pan, the caret revealed, the drag guard.
- `app-start.test.ts`: "Start engine" (`app/start.ts`): `startOffer` in each of the sixteen states, `startEngine` on the
  real controllers; pasted lines (`log/pasterun.ts`): `pastePlan`, `putBack`, `startFirst`'s toasts, another tab taking the
  engine.
- `wakelock.test.ts`: the screen wake lock (`app/wakelock.ts`) with fakes: the policy per state, taken for a run,
  refused, late and pending requests, no API.
- `files.test.ts`: store and engine worker together: the journal, what a run changed, a worker that cannot open its

- `machine.test.ts`: the state machine.

- `files-ui.test.ts`: the file panel's and tabs' logic (step 4a, `src/app/files/*.ts`) over fake-indexeddb.

- `client.test.ts`: engine client and worker transport: downloading start files into the Cache (size checks, abort,
  build
  mismatch, stale entries), start and end rules, error kinds, interrupt (`run()` clears the buffer as it posts; a lost
  SIGINT is written again while the run is on, never into the next run); store failures (`started` with `storeFailed`,

- `part-header.test.ts`: the shared buffer the graphics part is handed over in (`engine/lazy-part.ts`): what the page's

- `lazy-part.test.ts`: the worker's decisions about the lazy graphics part (`engine/lazy-part.ts`): what a waiting graph

  without a current snapshot).

- `site.test.ts`: step 5's landing and commands pages (`scripts/site-pages.ts`, `src/site/filter.ts`); the denied commands come from `commands.json`, generated from `browser.DENIED`.

### End-to-end (Playwright, `web/e2e/`, each test in 4 browser profiles)

Each test runs in Chromium, Firefox, WebKit and an iPhone profile. Skipped cases:
- The capped normal boot outside Chromium; the `?snapshot=0` normal boot in the two WebKit projects (its package load
  stalls now and then on Linux).
- The folder upload outside Chromium (Playwright cannot give a folder to an input).
- A menu item's click focus in WebKit and the iPhone (Safari does not focus a clicked button).
- On the desktop profiles: the iPhone-only checks, the phone's file dropdown, strip and command line Run button.
- On the iPhone: the desktop-only tests (a tablist with no scroll group, a renamed row drawn late, the unsplit Output
  tabs by keyboard), the folded file list's rename, the .dta tab's focus, the banner's hand-off to a .dta tab.

  `shell` and `webuse` marked off; the filter and its count; no help-page link or manual wording.
- `sample.spec.ts` (step 5): the sample project.
  - A first visit lists the sample and opens `analysis.do`; a later visit writes nothing; never over a visitor's files.
  - Restore the sample as an upload: toast, "already here", the clash dialog (Keep mine, Replace with the sample).
  - The sample runs in the real engine at the editor's base to a table and a graph.
  - Where the browser keeps no storage, the sample's write brings no banner and the visitor's own change does.
- `start-and-lock.spec.ts`: download counts, damaged cache, restart without cache, tab lock take-over, no test hook without the
  URL flag.
- `hook.ts` and `seed.ts` (no tests): the hook's type (`DofileHook`, from `src/main.tsx`) and the named helpers that
  put the page's state in a shape (an engine state, a banner, log items, ...); `fixtures.ts` holds the helpers shared by
  several specs (`isPhone`, `ready`, `settled`, `settle`, `putFiles`, `storedText`, `SAMPLE`, and the locators `toastOf`, `bannerOf`, `statusBar`, `toolbarOf`).
  `settle(page)` replaces a fixed sleep that asserts "nothing moved after this" (a late focus, a late write, a key's late
  effect): three frames, each followed by a task, and with `{ store: true }` a read of the store between them. Use it after
  the expected event, so the test still fails when the late move exists; a move from a timer longer than a few frames is
  not covered. The sleeps that remain guard something else: a loop that must be running before Break (`engine.spec.ts`,
  `graphics.spec.ts`, `editor.spec.ts` Break), a sample seed that must not write (`sample.spec.ts`), and a run, dialog or
  download that must not start (`editor.spec.ts`).
- `fixtures.spec.ts` (no browser page): `retryFirstGoto` in `fixtures.ts`, which the `page` fixture applies to every
  test's page (and `engine.spec.ts`, `start-and-lock.spec.ts` and `states.spec.ts` to pages they open themselves). A timeout on
  a page still at `about:blank` is retried once and logs "timed out on a fresh page" (WebKit bug 325840); a second
  timeout, another error, or a page that has left `about:blank` is not retried.
- `engine.spec.ts`: runs `.do` code in a real browser, legacy `.xls` and ReadStat formats, the memory snapshot start;
  the memory cap (`?memcap=400`: a 10-million-row `generate` is r(909), the engine stays `ready`, the data is kept),
  also
  on the normal boot (`?snapshot=0&memcap=400`, Chromium only); a streamed run (six lines, 200 ms apart: the log shows
  them in order while the run goes, in steps that each extend the last, and complete at the end) and, with
  `DOFILE_STREAM_BENCH=1`, a measurement of the log's cost per chunk over 50 and 500 lines (no assertion beyond the run
  completing).
- `graphics.spec.ts` (experiment E1c, a lazy snapshot only; skipped without a graphics part): the part's request held or
  refused with `page.route`. A run at ready that draws nothing does not wait for it; a Break while a graph waits is rc 1
  with the data kept and the part fetched once; "Graphs loading" and its ring while it downloads (every project, the
  phone's strip on iphone); written and imported while idle; a graph that waits while it lands draws; a return visit reads
  it from the Cache and a run at ready ends before the part is unpacked (not WebKit); offline on a first visit a graph is
  r(199) with a clear message, no lasting label, and the next graph once online fetches it and draws.
  - A return visit (a persistent profile, so every project): the page's "landed (cache)" line comes before "ready" (the
    page's own clock), a graph sent at ready draws, the part is written once and fetched once.
  - A damaged part: the graph says it arrived damaged, the Cache entry is dropped, the next graph fetches it and draws.
  - Without cross-origin isolation (no SharedArrayBuffer): the worker alone makes one `fetch()` of the part and the
    graph's synchronous XHR one request, the page never fetches it; a graph at ready draws without waiting for a held
    fetch and its log says it waits for the files; the ring shows the download (told by the worker) and goes when it lands;
    other runs work. A damaged part's retry goes to an address of its own (`fresh=`), not the HTTP cache's.
- `output.spec.ts` (step 4c): the Output tabs; Copy image twice in the full-size view (fake clock: the first "Copied" timer
  does not clear the second).
  - The three empty states and the reset wording; a .png on the light card in the dark theme; .dta tabs with no engine.
  - With an engine: the Graph tab and full-size view (Copy image, Export PNG), the Data tab (filter, Show 50 more), the
    Results tab (sections, Globals without the presets, copying, matrices), a .dta tab (variables, Load).
  - The clipboard is a recorder in every page.

### Screenshot run (Playwright, `web/screenshots/`, outside `npm run e2e` and CI)

Not a test suite: `npm run shots:baseline -- <commit>` builds a commit in a worktree of its own and takes one screenshot
of each state of a fixed list into `web/.shots/baseline/` (git ignores `.shots/`); `npm run shots` builds this tree
and compares each state with it (plan rule 10: a view move changes no pixel). Its own config (`screenshots.config.ts`:
Chromium and the iPhone profile only, one worker, no retry), its own folder, no CI job. `shots.spec.ts` holds the
list: the engine walk (ready with the sample, the log after a run, a results table, the graph and its full-size view,
a .dta view; the status bar's run time and memory are put back to fixed values), several tabs with one unsaved, each dialog,
each menu open, the tree with a rename field and with a draft row, a log with an error, each banner, the phone's three
views. The states are seeded through `e2e/seed.ts`.

## Conformance corpus: value and limits

**Why it is worth keeping**
- It is the only independent numerical oracle: `ref.json` comes from statsmodels and linearmodels, while the vendored
  suite compares OpenDTA with its own expectations and cannot catch a wrong result it gives consistently.
- It runs where the other suites do not: through dofile's `Engine` with the sandbox on, and in Pyodide, where
  `check-snapshot` compares the browser's output with CPython's.
- A strict xfail turns a fixed upstream gap into a failing test, so the xfail gets removed.
- The probes found a real bug (`xtlogit, re` crashed; see `docs/archive/engine-evaluation.md`). It is cheap: a few dozen
  cases.

**Limits**
- Narrow numeric coverage: mostly OLS, IV, logit, probit, Poisson, fixed effects and clustered standard errors.
  Survival, multilevel, SEM, time series and nonparametric tests have no independent reference; the Stata 14 log
  comparisons cover far more, as does the vendored suite for basic regression.
- Not every check is independent: the data-management, programming and error checks (counts, `wordcount`, `err_*_rc`)
  are regression tests with expected values set by hand.
- The probes assert rc 0 only, so a wrong output passes. Two probes are expected failures (`esttab`, `outreg2`).
- The one xfail among the value checks (`reghdfe`, GAP-1) is a missing community command, not a bug, so it will never
  flip by an upstream fix.
- The tolerance is 1e-6 relative for every value; iterative estimators (nonlinear, multilevel) may need a looser one.

**Recommendations to broaden it** (none done yet; roughly cheapest first)
1. Make each probe check one key number against a reference, so a probe fails on a wrong result as well as on a crash.
2. Add statsmodels references for more estimators already in the vendored suite: `xtreg, re`, `xtreg, be`, `glm`,
   `tobit` or `truncreg`, `ologit` and `mlogit`, `nbreg`.
3. Add survival (`stcox`, `streg`; lifelines or statsmodels) and time series (`arima`, `var`; statsmodels).
4. Add summary-statistics and test commands with closed forms or scipy references: `ttest`, `ranksum`, `tabulate`
   with chi-squared, `correlate`, `pwcorr`, `ci`.
5. Allow a per-value tolerance in `ref.json` for iterative estimators.
6. Separate the hand-set checks (data management, programming, errors) from the reference-backed ones, in different
   corpus files or a different marker, so a green run says which kind of check passed.
7. Keep `eval/`'s reference generator (`make_data.py`, `reference.py`, removed 2026-11-10, in git history at commit
   `10e0f1c`) in the repo or restore it, so new references can be regenerated. Today `ref.json` has no generator.

## What is not covered

- Component rendering and styling are checked only by the e2e tests (each in four profiles); the unit tests drive the
  controllers,
  not the Preact views.
- The Pyodide engine against CPython: `check-snapshot` runs in CI on a pull request and on a push to `main` (`web.yml`,
  the snapshot job; on `main` `deploy.yml` calls `web.yml` and deploys only if it, `ci.yml` and `lint.yml` passed);
  `check-pytest` and `check-numeric` are run by hand. The three check scripts share `web/scripts/lib/` (argument parser,
  shard pool, repo paths, `wheels()`); nothing tests them but running them.
- Probes check rc 0 only, not output.
